Detection engineering · in production

Four SIEM log parsers, designed as one coherent set

Four sources on the public web access chain were collected but never parsed: stored as raw text, invisible to search, impossible to correlate. I wrote a custom XML parser for each in NetWitness (Log Parser Tool v2) and mapped every field to the platform’s Unified Data Model.

The hard part was semantics, not extraction: choosing the right meta-key among hundreds, avoiding reserved and deprecated ones, and freezing the shared pivot keys across all four parsers first — because a mismatch raises no error. Correlation just fails, silently.

Risk-based prioritisation · research prototype

WARS — ranking exposed web assets by real risk

Sorted by CVSS alone, a vulnerability list quickly becomes a wall of “criticals”: two 9.8s look identical. WARS (Weighted Asset Risk Score) adds what CVSS deliberately leaves out — how likely exploitation is and how much the affected asset matters — to answer one question: what do we fix first on Monday morning?

I designed and built it end to end in Python, within the asset-based approach of ISO/IEC 27005. Each asset gets a 0–100 score, a P1–P5 band and a factor-by-factor breakdown that can be defended in front of an auditor.

  • asyncio
  • httpx
  • Playwright
  • Pydantic
  • LangGraph

  1. 01

    Discover

    What is visible from the Internet?

    Passive crawl only: GET and HEAD requests, robots.txt respected, conservative rate limits.

    httpx · asyncio · defusedxml

  2. 02

    Classify

    What does each asset do?

    Information, business process or both — and how sensitive. The only step where an LLM is used.

    LangGraph · LLM · rule layer

  3. 03

    Assess

    What could happen, and how bad?

    Findings enriched with CVSS from NVD, EPSS exploitation likelihood, CISA KEV and MITRE ATT&CK techniques.

    NVD · EPSS · KEV · ATT&CK

  4. 04

    Report

    What do we fix first?

    Self-contained HTML/PDF report ranked P1–P5, every score broken down factor by factor, TLP 2.0 marked.

    Playwright · HTML · PDF

Each step is a standalone script that hands validated JSON (Pydantic) to the next — so any step can be replayed and audited on its own.

Design decisions I stand by

  • The model never touches a number. The LLM only answers “what is this asset?”. Factors, formula and thresholds are deterministic, so every score can be justified line by line — and the tool still runs on its rules without an API key.
  • Multiply, don’t add. If one factor is close to zero the score must collapse: a severe flaw on an asset with no business value should not top the list.
  • Known exploitation is a floor. A CISA KEV match keeps the score in the critical band, whatever the other factors say.
  • Uncertainty counts as risk. A doubtful classification, a failed step or a missing source sends the asset to human review — never silently to low priority.

What I don’t claim: the weighting is argued, not yet statistically validated. The next step is to calibrate it against real remediation decisions.
